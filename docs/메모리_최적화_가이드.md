# 메모리 최적화 권장사항 로그 해결 가이드

## 📋 문제 설명

서버 실행 중 다음과 같은 로그가 반복적으로 출력되는 경우:

```
⚠️ 메모리 최적화 권장사항: [
  {
    priority: 'high',
    action: 'immediate_cleanup',
    description: '즉시 캐시 정리 및 가비지 컬렉션 실행 필요'
  },
  {
    priority: 'medium',
    action: 'reduce_cache_ttl',
    description: '캐시 TTL 단축으로 메모리 사용량 감소'
  }
]
```

## 🔍 발생 원인

1. **높은 메모리 사용률**: Heap 메모리 사용률이 설정된 임계값(85~95%) 이상
2. **메모리 제한 부족**: Node.js의 기본 메모리 제한이 작업 부하에 비해 부족
3. **메모리 누수**: 캐시나 메모리에 누적된 데이터가 정리되지 않음
4. **가비지 컬렉션 미실행**: `--expose-gc` 플래그 없이 실행

## ✅ 적용된 해결 방법

### 1. Node.js 메모리 할당 증가
`ecosystem.config.js` 파일에 `--max-old-space-size` 옵션 추가:

```javascript
node_args: '--expose-gc --max-old-space-size=512',
```

- 기본값: 약 512MB (Node.js 버전에 따라 다름)
- 변경값: 512MB로 명시적 설정
- 필요시 768MB 또는 1024MB로 증가 가능

### 2. 메모리 경고 임계값 조정

**변경 전:**
- 경고(warning): 75%
- 긴급(critical): 90%
- 권장사항 출력: 85% 이상

**변경 후:**
- 경고(warning): 85%
- 긴급(critical): 95%
- 권장사항 출력: 90% 이상

### 3. 가비지 컬렉션 임계값 조정
자동 가비지 컬렉션 실행 임계값: **80% → 90%**


## 🔧 추가 최적화 옵션

### 메모리 할당 더 늘리기
메모리가 충분한 서버인 경우:

```javascript
// ecosystem.config.js
node_args: '--expose-gc --max-old-space-size=1024',  // 1GB
```

### 캐시 TTL 단축
`utils/cacheManager.js`에서 캐시 만료 시간 조정:

```javascript
this.cacheConfig = {
    nutrition: { ttl: 300 }, // 10분 → 5분
    user: { ttl: 180 } // 5분 → 3분
};
```

### 메모리 정리 주기 단축
주기적인 메모리 정리 간격을 더 짧게:

```javascript
// server.js
cron.schedule('*/5 * * * *', performMemoryCleanup); // 10분 → 5분
```

## ⚠️ 주의사항

1. **메모리 할당량 증가 시**: 서버의 물리적 메모리를 고려
2. **임계값 너무 높게 설정**: Out of Memory 에러 발생 가능
3. **캐시 TTL 너무 짧게**: 성능 저하 (DB/API 요청 증가)
